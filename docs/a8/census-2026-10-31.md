# The A8 census of 2026-10-31: bsv-rs, the speed cell

The rows of `census-2026-10-31.json` (the same rows, with each one's size bands, nearest callers and producing run in full), sorted by share of their run. One run per corpus; a share is the function's self (leaf) samples over all samples of its run. No candidate is named here (the charter's section 1 and section 2; the keeper and the owner judge the rows).

Crate commit `099d5d98` (`099d5d98710bf2d4dcd568f24683cc781b3596c9`). Host Johns-Mac-Studio (Apple M1 Max, 32 GiB, macOS 26.7.1). Profiler samply 0.13.1. Toolchain rustc 1.99.0.

## Method

Each corpus is replayed by one process of a harness kept out of the tree (`/Volumes/Lanes/out/bsv-rs/a8-census-1031/harness`, a crate depending on this worktree by path, features `full`, release profile with `debug = true`). `scripts` runs `tests/conformance_scripts.rs`'s own evaluation code, copied with its `support/` files, the corpus file parsed once per process. On each pass it replays the sibling's 5,116 evaluation vectors through `Spend`, the sighash builder and `Transaction` as the test does, and one full pass reproduced the test's pinned totals (4,120 run, 4,109 passed, 959 unsupported, 37 skipped, 11 known failures, 0 failures, 0 panics). `beef` runs every BEEF of the BEEF corpus through `Beef::from_binary` + `verify_valid(false)`, `verify_stream`, `verify_stream_structure` (headers that accept every root) and `Transaction::from_beef`, and every BUMP through `MerklePath::from_binary` + `compute_root`. `wire` runs every recorded request frame through `WalletWireProcessor::process_message` over a `ProtoWallet` and through the bench's reader/writer layouts (`benches/wire_codec/support.rs`), and every response frame through its result or error layout. Each process repeats its corpus until 45 s of replay have passed (`A8_SECONDS=45`), on one thread, under `samply record --save-only --unstable-presymbolicate` (1 ms sampling interval). `tools/analyze.py` reads the saved profile and its symbol file, attributing each sample to its leaf function for the self share and to every distinct function on its stack for the inclusive share; it resolves the harness binary's remaining addresses with `atos`. Every function above 1% self is a row. A function's input size is the one named in the size rule of its corpus. For `dominates_from_input_size` each corpus was rerun in size bands for 20 s each: scripts in quartiles plus its top 1% (5 bands), beef in quartiles with the top quartile split at 8,000 B (5 bands), and wire in 4 bands (most frames are the 18-byte error frames). A function leads a band when it ranks first by self share there. The verdict names the size from which it leads, `leads below`, `leads at every size` or `never leads`, the latter with its highest rank. Limits, stated: inlined functions count toward the function they were inlined into (the symbols carry no inline frames); libsystem_malloc carries no symbols here, so the allocator is one row per run; the `path` fields (the nearest `bsv_rs` frame on the stack and the share of the function's self samples that have one) separate the crate's path from the replay's own code (the copied test's hex decoding, `serde_json` value access and its classification), and a row whose `self_samples_with_a_bsv_rs_frame` is 0 is replay code, not the crate's; the host was shared: `uptime` at 15:33 local (19:33Z), minutes after the runs, read load averages of 61.09, 74.50 and 68.83 on 10 cores, so the replay walls (in `runs.jsonl`) are not this machine's quiet figures. That reading is the only load record: `runs.jsonl` carries none per run. The rerun path: build the harness (`A8_WORKTREE=<the tree> cargo build --release` in the harness folder, its `Cargo.toml` naming the tree by path, at the commit above), then feed `tools/run.sh` in the evidence folder its `corpus band lo hi seconds` lines (the bands of the producing-runs table) on a quiet host, recording `uptime` beside each run, and `tools/analyze.py` per profile. A share is a ratio within one process's samples, but samply 0.13.1's per-sample CPU deltas (`threadCPUDelta` summed over each full profile: 6.69 s of CPU in 45.25 s for scripts, 6.84 s in 46.39 s for beef, 4.45 s in 45.19 s for wire, a single-threaded replay each) were not used to correct it: the shares count samples, descheduled time included.

## The corpora

The sibling files (the scripts corpus and the BEEF corpus's merkle-path.json, serialization.json and regressions) were read from the clone at `~/bsv/ts-stack`, HEAD `4d0ea63c85a836e3509291babb0d8e0c784b70a0`, those files clean in its working tree; they are byte-identical at `edf6e03`, the reference pin named in `CLAUDE.md` (`git diff 4d0ea63 edf6e03` over them is empty). Neither `tests/conformance_scripts.rs` nor `tests/conformance_beef.rs` pins a commit: each reads whatever `BSV_CONFORMANCE_DIR` (default `../ts-stack/conformance`) holds, checks only that `META.json` exists, and pins vector counts; the corpus carries no `PROVENANCE.md`.

Size rule: an item's size: the BEEF's or the BUMP's bytes.
- `scripts`: the sibling's conformance corpus: ts-stack conformance/vectors/sdk/scripts/evaluation.json at ts-stack 4d0ea63c8, 5,116 vectors (2,922 node-script, 2,000 node-sighash, 161 node-transaction, 33 misc), replayed through Spend as tests/conformance_scripts.rs does (that file's code, copied into the harness; 37 corpus-skipped vectors not run); the census totals held: total=5116 run=4120 passed=4109 unsupported=959 skipped=37 known_failures=11 failures=0 panics=0. Size rule: a vector's size: the bytes of every *_hex string under its input (scriptSig, scriptPubKey, transaction).
- `wire`: the wallet wire fixtures: tests/fixtures/wire/*.json, 29 files, 323 cases (56 call cases: 28 calls x minimal/full; 267 error-frame cases), 378 non-empty recorded frames (56 request frames and 322 of the 323 response frames; `error_frames.json` records one empty response; 1 to 303 B, 12,251 B in all); every request frame through WalletWireProcessor::process_message over a ProtoWallet (fixed key) and through the bench's reader/writer layouts (benches/wire_codec/support.rs), every response frame through the result or error layout. Size rule: a frame's size: its bytes.
