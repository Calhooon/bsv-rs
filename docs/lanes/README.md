# Lanes of the north-star programme (epic #101)

A lane is one issue of the programme, worked in its own worktree on a branch from `origin/beta`, landed by the captain through a PR into `beta`. The briefs here are the records of what each lane was asked; the lane's report is its reply. The shared rules, which every brief assumes:

1. **Where you work.** The worktree cca gives you, on a branch from `origin/beta` (never `main`; `main` is the stable line). `CARGO_TARGET_DIR` under `~/bsv/targets/` or `/Volumes/Lanes/targets/`, never inside the checkout and never a literal `/tmp`. Never the repository's own checkout, never a secrets file, never `~/vault/`, never `~/bsv/bsv-low/`. Anything you keep for the project beyond the branch (evidence, runs, corpora too large for git) goes under `/Volumes/Lanes/out/bsv-rs/<lane>/`.
2. **The proof rule.** Every claim with its command and the last lines of its output in the report. A test you did not run is not a test. `[X]` run, `[D]` told.
3. **No network except reads.** No broadcast, no wallet call, no sats. A test that needs an HTTP answer uses `wiremock` (CLAUDE.md rule 4).
4. **The references, at pins.** The TypeScript SDK and Go SDK as CLAUDE.md rule 1 reads them. BRC-100 and the wallet BRCs at the line's pin of `bsv-blockchain/BRCs`, `ed1b015` (2026-10-05; the stack's `docs/PROVENANCE.md`, the keeper's word of 2026-10-23), read with `git -C ~/bsv/brcs show ed1b015:wallet/0100.md`, never a working tree. Every citation is a line number at `ed1b015`; where `5119a9b` (upstream/master, 2026-10-19, not on the line) reads the same, say so in a clause; where it differs (listOutputs' `totalOutputs` and `spendable`, internalizeAction's `customInstructions` bound), cite both and mark the newer "upstream, not on the line". A pin moves only by the keeper's recon and the owner's word, across the three crates in one step. The stack's lane rules `~/bsv/bsv-stack-lean/docs/lanes/l2-README.md` (the six tests T1 to T6, which your report names for each design choice). The node's harness `~/bsv/bsv-script-lean/harness/README.md` (the evaluator is the oracle, the corpus is the judge): any change under `src/script/` or `src/transaction/` ships with a `harness/run --impl bsv-rs --corpus seed` before and after, identical.
5. **One concern per PR.** A refactor never carries a behavior change; a behavior change changes its fixture in its own commit. The gate, green before the report: `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --features "full,http,websocket" --no-fail-fast`, `cargo test --doc --all-features`, `cargo build --examples --all-features`, `cargo test --test readme_examples`, and the wasm32 build of CLAUDE.md rule 6.
6. **Nothing panics on input; wasm32 is a target of every change** (CLAUDE.md rules 5 and 6).
7. **Wording.** No em dash. Never "first", never "conformant" without a run. No hostname of a deployment, no token shape, no account id, no key material in a fixture or a log.
8. **Never push, never a PR.** The branch stays in your worktree; the captain fetches it, runs the cold review, pushes it to origin and opens the PR. (A pushed branch is scanned by the `secrets` job on every PR; a seed corpus or a vector that looks like a key fails every PR in the repository until it is allowlisted in `.gitleaks.toml` with its reason.)
9. **The report.** The opening line is `REPORT: STATUS done|blocked`, then the base commit, your tip commit, the files, the commands and their tails, what is `[D]`, what you did not run and why, and what the captain must do at landing. Stop and say so when a step needs a word that is not yours: a public API's shape, a pin, a tag or release, a spend.
10. **Bounds.** The brief's hours are the limit; past them, `STATUS blocked` with what remains.
11. **Never let one command run ten minutes; everything in the foreground.** The tool that runs your commands stops any single command at ten minutes and moves it "to the background"; a lane's session ends with its turn, so a lane that then waits for a notification never gets one and its REPORT is never written (six lanes lost their turn that way on 2026-10-24, on Codex, Opus and Fable alike). Compile before you run: `cargo test --features "full,http,websocket" --no-run` (if that alone is cut, run it again; it resumes), then run the compiled suite with `--no-fail-fast`; split anything else that nears the cap (`--lib` then `--tests`, two `--test` halves, each fuzz target 30 seconds). Never a background command, never a detached script, never a promise to report later; the last thing you print is the complete REPORT. A RED-before check runs in a scratch copy with its own `CARGO_TARGET_DIR`: a shared one hands the GREEN run another tree's build.
