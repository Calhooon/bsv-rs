## The resolution, pair by pair

Counts from the files (`grep -c '#\[test\]'`, `grep -c '#\[tokio::test'`): 8, 9 and 7,
equal in both copies of each pair; the gate and Modules cells were equal too
(`default` / `primitives`, `script` for the two script files, no `required-features`
entry in `Cargo.toml`; `wallet`+`http` / `wallet` for the transport file, its
`#![cfg(all(feature = "wallet", feature = "http"))]`). Only the descriptions differed.

- `script_int64_operand_witness.rs` (194 and 196): the contradiction. Line 194 said the
  witness's 9-byte offset (ninth byte `0x80`) "is 4" under a word and "the default mode
  keeps the script-number reading"; line 196 said it "is -4 under a word, the node's
  checked sign-magnitude decoder; the default mode reads its first 8 bytes, 4, valid".
  The tests decide for 196: `the_witness_is_a_range_refusal_under_the_block_word` and
  `..._standard_word` assert `OP_SUBSTR offset (-4) must be in range [0, 16) ...`, and
  `the_witness_is_valid_in_the_default_mode` asserts `Ok(true)` (the reference's reading
  since #382). Line 194 is the text from before #41 and #382, both halves inverted; it
  is removed, 196 kept.
- `script_shift_count_witness.rs` (192 and 195): line 195 said "the default mode shifts
  by any count", the text from before #383; line 192 says the default mode refuses a
  count above `INT_MAX` in the reference's words since #383, a verdict under a caller's
  budget too, as `the_witness_is_the_references_int_max_refusal_in_the_default_mode`,
  `a_left_shift_by_int_max_plus_1_overflows_before_the_count_test` and
  `a_zero_value_follows_the_same_tests` assert. 192 kept, 195 removed.
- `transport_fault_wallet.rs` (104 and 106): the same sentence, 106 adding that
  `HttpWalletJson` is configured with an originator since #323, as the file's
  `HttpWalletJson::with_client(.., Some("app.example.com".into()), ..)` is. 106 kept,
  104 removed.

## The key is the stem (the #715 fold)

The scoped read of `67ad7d28` found the check keyed by the backticked name while the
readers it protects key by the stem: the guard's `test_rows` by `name.rsplit('/')` less
`.rs`, `nightly_mutants.test_rows` by `Path(name).stem`. So a `support/a.rs` row beside an
`a.rs` row is one row to every reader (the later wins) and passed the check. The fold
keys the check by the stem and takes it from the readers' own reading, not a copy: in
the guard, `table_rows` (each row's line number, text and `.rs` names) and `stem` feed
both `test_rows` and `doubled_rows`; in Python, `nightly_mutants.table_rows` yields
`(name, stem)` per file and both `test_rows` and `rows_from_sources.doubled_rows` read it.

files and each row's line:
