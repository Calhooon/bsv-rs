# #760: the lookup resolver's host accounting is the reference's

Base `8601c66b` (`origin/beta`'s tip at the lane's start, #732 landed).

## The reference

`ts-stack@edf6e03`, `packages/sdk/src/overlay-tools/LookupResolver.ts`,
`completeTrackedLookup`:

- `:2388-2392`: an answer `normalizeLookupAnswer` cannot read (neither an
  output list nor freeform) is `recordFailure(host, 'Malformed lookup
  response')`, thrown;
- `:2395-2398`: `isOutputListAnswer` (an array of at most the output cap, each
  output well formed: the empty array passes, `:412-428`), then
  `recordSuccess(host, latency)`;
- `:2399-2402`: "A valid freeform response is neutral: it proves this request
  reached the service, but it must not erase an availability backoff
  established by a concurrent failing request and cannot contribute to
  output aggregation." Then `if (isFreeformAnswer(normalizedAnswer)) return
  normalizedAnswer`: no call on the tracker at all (no success, no latency,
  no failure).

`ts-sdk@9e3ede6`, `src/overlay-tools/LookupResolver.ts:518-528`:
`answer.type === 'output-list' && Array.isArray((answer).outputs)`, then
`recordSuccess`, else `recordFailure(host, 'Invalid lookup response')`: the
empty array a success, a freeform answer a failure.

## The change

`src/overlay/lookup_resolver/query.rs`, one match on the answer:

| Answer | Before (`8601c66b`) | After |
|---|---|---|
| output list, at least one output | success | success |
| output list, empty | failure, `Invalid lookup response` | success |
| freeform | success (clears a backoff) | nothing recorded |
| formula | failure, `Invalid lookup response` | unchanged |
| lookup error | failure, the error's text | unchanged |

The text `Invalid lookup response` is the tracker's recorded reason
(`last_error`, the rank event's reason), no `Error` variant; no reader in the
crate or its tests matches on it, and it is `ts-sdk@9e3ede6`'s own text for
the same answers (`:527`; `edf6e03` says `Malformed lookup response`).

The tracker's arithmetic (`host_reputation_tracker.rs`): `record_failure`
counts consecutive failures, two of grace (`grace_failures: 2`), the third
backs the host off 1 s doubling to 60 s; `record_success` sets the count and
the backoff to zero. So three empty answers backed a host off, and a freeform
answer between failures reset the count.
