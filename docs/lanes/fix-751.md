strength. All three changed the same lines. In `query`'s refusal list the

The rule read's FIX, ported: `query` sent its attributes as a
`serde_json::Value` writes them, sorted by bytes, while `query_bounds::check`

insertion order as `resolve_by_attributes` sends them (#394). The check walks
them through `client_attributes::js_order`, which puts array-index names
ahead, as `JSON.parse` holds them. The recorder's claim (each case is the
question `query` sends) is now true. The recorded witness is
`two_faults_index_value_then_name`, added to the recorder (`a.b`, then `7`

addition; two runs under Node v22.18.0 are byte-identical, and the vector now
has 68 questions.
