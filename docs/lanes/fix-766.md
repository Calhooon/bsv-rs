# #766: the atomic writer copies no BUMP for a txid-only entry without a matching index

Base `e7f5d4f7` (`origin/beta`'s tip at the lane's start, #769 landed).

## The site, side by side

| | Reference (`ts-stack@edf6e03` `packages/sdk/src/transaction/Beef.ts`) | `atomic_closure` at `e7f5d4f7` | Tip |
|---|---|---|---|
| a txid-only entry whose index names a BUMP holding its txid | `#copySelectedTransactions` `:448-470`: that BUMP copied, the index mapped | the same | the same |
| an entry with no index | skipped at `:453`; copied as `BeefTx.fromTxid(txid, undefined)` | the last BUMP holding the txid (`rposition`), its index mapped | no BUMP, no index |
| an index naming a BUMP that does not hold the txid | `#hasMatchingBump` `:436-446` false: skipped, `bumpIndexMap.get` `undefined` | the last BUMP holding the txid | no BUMP, no index |

The change is one line: `tx.bump_index().filter(|_| self.proves(tx))`, the
`rposition` fallback removed. The closure walk (stopping at a proven or
txid-only entry), a raw entry's BUMP and the merge doors' last-BUMP rule
(#757, #765) are unchanged.
