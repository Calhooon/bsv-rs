# Lane fix-880: Shamir recovery interpolates with one inverse for the whole set (#880)

Base: `origin/beta` at `3e1ade84`. Reference: `ts-stack@edf6e03` (`packages/sdk/src/primitives/Polynomial.ts`, `PrivateKey.ts`); go-sdk at `2ca481c` (`primitives/keyshares/polynomial.go`). Host: Apple M5 Max, 18 cores, macOS.

## The decision

`Polynomial::value_at` returns the same field element for every input it accepted, computed with one modular inverse per call (Montgomery's batch inversion over the per-share denominators). No wire byte, key, refusal, refusal order or word moves, so no divergence row: the reference decides answers, and cost is where it is indifferent.

## The site, side by side

The reference (`Polynomial.ts:120-136` at `edf6e03`), one `invm` per ordered pair:

```ts
for (let i = 0; i < this.threshold; i++) {
  let term = this.points[i].y
  for (let j = 0; j < this.threshold; j++) {
    if (i !== j) {
      const xj = this.points[j].x
      const xi = this.points[i].x
      const numerator = normalizedX.sub(xj).umod(P)
      const denominator = xi.sub(xj).umod(P)
      const denominatorInverse = denominator.invm(P)
      const fraction = numerator.mul(denominatorInverse).umod(P)
      term = term.mul(fraction).umod(P)
    }
  }
  y = y.add(term).umod(P)
}
```

go-sdk the same loop (`polynomial.go:82-106`), a missing inverse read as 0 (`:92-95`). This crate on the base (`src/primitives/bsv/polynomial.rs:259-297` at `3e1ade84`): the same loop over `min(points.len(), threshold)` points, `mod_inverse(..).unwrap_or_else(zero)` in the inner loop. Its one caller in `src/` is `interpolate` (`src/primitives/bsv/shamir.rs:382-404`), serving `KeyShares::recover_private_key` and `recover_private_key_from_legacy_backup`.

This crate now:

```text
N_i = Π(j≠i) (x - x_j)      by the products of the factors before i and after i
D_i = Π(j≠i) (x_i - x_j)    t(t-1) multiplications
the non-zero D_i inverted together: running products, ONE mod_inverse, the walk back
y   = Σ y_i * N_i * D_i^-1  (a D_i of 0 contributes 0)
```

Why the value is the same: p is prime, every `(x_i - x_j) mod p` is in `[0, p)`, and the product of the inverses is the inverse of the product; where one factor is 0 the pairwise loop multiplied the term by a zero inverse (term 0) and the batched one skips the term (0). Every intermediate is reduced into `[0, p)`, so the representative is the same too. The cells the public door keeps (the fields are public): no points 0; one point `y mod p`; a threshold past the point count uses the points there are; any `x`; coordinates at or past p or negative.

Constant time: none before, none claimed. Kept: every inverse's input and the one data branch (`D_i == 0`) are functions of the x coordinates alone; a `y` enters only as a factor.
