# #616: PushDrop's canonical refusal, the field bounds before the envelope

Base `9cf60844` (`origin/beta`'s tip at the lane's start). The issue, from the
#614 cold read: a token without `OP_CHECKSIG` second, with the right field
count and one oversized field, took the envelope's words from
`canonical_refusal` (`src/script/templates/pushdrop_position.rs`), where the
reference's `decodeCanonicalPushDrop` (`ts-stack@edf6e03`
`packages/sdk/src/script/templates/PushDropValidation.ts:54-79`) checks the
bounds first (`:63-73`).

`canonical_refusal` runs only where this crate's lock-before read
(`PushDrop::decode_before`) refuses a token the reference's `PushDrop.decode`
reads (a token without `OP_CHECKSIG` second, a key alone): it reproduces the
reference's refusal over the whole script. Its callers are the five
`decodeCanonicalPushDrop` sites (the local store's `local_parser_words.rs`,
the kvstore interpreter's `token_validation.rs`, the registry's `token.rs`,
the overlay admin token's `admin_token_validation.rs`, the storage
downloader's `advertisement.rs`); each now passes its own `maximumFieldBytes`
and `maximumPayloadBytes`, the constants its success path already checks.
