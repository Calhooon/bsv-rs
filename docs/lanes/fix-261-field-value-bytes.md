## The rule (a MUST; cite every line you read)

BRC-52 at the pin (`git -C ~/bsv/brcs show 5119a9b:peer-to-peer/0052.md`, lines 89 and 97): a field value is a base64 string, and "Field values in CertificateBinary are the UTF-8 bytes of the Base64 string, not the Base64-decoded ciphertext bytes. Serializers and verifiers MUST preserve the field-name strings and Base64 text used in the signed representation. They MUST NOT apply ... Base64 decoding and re-encoding to an existing signed field while reconstructing its preimage." The reference (`~/bsv/ts-stack` at `edf6e03`): `packages/sdk/src/auth/certificates/Certificate.ts:294-296` writes `UtilsToArray(fieldValue, 'utf8')`; `MasterCertificate.ts:283` stores `toBase64(ciphertext)` as the field. Go (`~/bsv/go-sdk` at `2ca481c`): `wallet/interfaces.go:122` `Fields map[string]string`, `auth/certificates/certificate.go:58-60` writes `[]byte(fieldValue)`. This crate's `Certificate.fields` is `HashMap<String, Vec<u8>>` (`src/auth/certificates/certificate.rs:82`) and its writer emits those bytes as held: the doc example at `:31` (`b"ZW1haWw="`) already reads the rule right. The sites that break it:

- `src/auth/utils/validation.rs:249-253` (and read `:264`): a certificate built from a JSON result decodes each field before `with_fields`.
- `src/identity/client.rs:1254-1256` and `:1429-1431`: the identity client's parsers decode each field before `set_field`.
- `src/auth/certificates/master.rs:85` with `:213`: `MasterCertificate` stores `encrypt_result.ciphertext` raw where the reference stores its base64.
- `Certificate`'s own serde: `fields` carries no `with`, so the JSON shape today is a number array per value where the reference's JSON (`Certificate.ts`'s `toJSON`/constructor, `Wallet.interfaces.ts` `WalletCertificate.fields: Record<CertificateFieldNameUnder50Bytes, string>`) is the base64 string. Read how the JSON substrate and the auth messages carry fields today and fix the serde so a value's held bytes go out as that UTF-8 string and a string's UTF-8 bytes come in; a value that is not valid UTF-8 is a refusal with a reason, never a panic (rule 5).
- Every decrypt site (`MasterCertificate::decrypt_fields`, `VerifiableCertificate`'s field decryption, the identity client's): decode the base64 text there, at decrypt time, and nowhere earlier. The keyring is outside the signature (`0052.md:238`); keep its representation unless the decrypt path forces a choice, and say what you did.

`grep -rn "from_base64\|to_base64" src/auth src/identity` for anything this list missed; every site is yours.
