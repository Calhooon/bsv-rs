## The finding (issue #329; the keeper's ruling of 2026-10-27 09:1xZ under the owner's ruling (c): go, before the 0.9.0-beta.2 cut)

`WalletInterface`'s 28 methods take `originator: &str` (`src/wallet/interface.rs:98-`), so an absent originator and `""` arrive at a wallet as one value, and a wallet behind the trait cannot give the reference's two verdicts: `validateOriginator(undefined)` accepts (`ts-stack@edf6e03` `packages/sdk/src/wallet/validationHelpers.ts:1003-1004`), `""` fails the 1 to 250 length rule (`:1006`). The reference's interface carries `originator?: OriginatorDomainNameStringUnder250Bytes` on all 28 methods (`packages/sdk/src/wallet/Wallet.interfaces.ts`, 28 sites). Go's takes `originator string` on all 28, `""` for none (`go-sdk@2ca481c` `wallet/interfaces.go`): the parity note. The binary wire already carries absence as a length-0 originator (`src/wallet/wire/transceiver.rs:120-123`) and the HTTP JSON substrate sends no header for an empty one (`src/wallet/substrates/http_json.rs:133-145`): only the in-process type changes.

## What to do

1. **The trait.** `originator: Option<&str>` on every method. Every implementer in this crate moves with it (`ProtoWallet`, `HttpWalletJson`, the mocks under `tests/` and in `src/kvstore/local.rs`), and every caller (`WalletClient`, `identity`, `kvstore`, `registry`, `auth`'s peer and certificate code, the examples, the doc tests): `None` where a client has no configured originator (the identity client after #318, the contacts manager, the kvstores, the registry client; what `WalletClient` carries when none is set), `Some(o)` where one is configured or given. `Some("")` passes through to the wallet as `Some("")`, the reference's `""` (never mapped to `None`). `ProtoWallet` ignores the originator as before.

The #323 lane (`lane/fix-323-http-substrate-originator`, running now) changes that substrate's own rule (the configured originator required at the call, both headers in the origin form, the per-call originator not used by the JSON substrate as the reference's is not): this issue is the call's parameter, that one the substrate's configuration; whichever lands first, the other rebases onto it, and the REPORT says what was merged.
