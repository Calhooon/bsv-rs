# The oracle's timeout judge: a timed-out mutant re-run once alone (#781)

Branch `lane/fix-781` from the record PR #780's tip, `8264a95d`
(`origin/lane/record-complete-1104`, the complete run's record on beta
`4ed58d05`). The keeper's word of 2026-11-04 15:2xZ: no margin on a floor; the
judge, not the floor, carries a timeout. A mutant that times out is re-run once,
alone, under the stated method; one that times out again leaves the score's
denominator as a timeout row, never a survivor and never a kill. No crate code
moves.

## The method

`nightly_mutants.py run`, after the shard's pass (`lone_reruns`): for every
outcome of the pass's `mutants.out/outcomes.json` whose summary is `Timeout`, in
order, a directory `rerun/<n>/` under the shard's root, a one-line diff of the
mutant's start line with its text unchanged (`line.diff`), and one cargo-mutants
run composed from the shard's own command (`lone_command`):

```text
cargo mutants --no-shuffle --features full,http --file <the shard's files> \
  --cargo-arg=--locked --cargo-arg=--lib --cargo-arg=--test=<each target> \
  --cargo-test-arg=-- --cargo-test-arg=--skip=<each skip> \
  --re '^<the name, escaped as regex::escape escapes>$' --in-diff rerun/<n>/line.diff \
  --minimum-test-timeout <the surface's> --timeout-multiplier 3 --build-timeout 300 \
  --jobs 1 --output rerun/<n>
```

The sharding (`--sharding round-robin --shard k/n`) is dropped, so the one
mutant is not lost to another shard's slot. The baseline runs (no `--baseline
skip`), so the re-run's test timeout is derived again from a baseline timed on
the shard as it is then: the base re-timed. `run.json` carries the mark
(`timeout_rerun: 1`, written before the pass, so an empty shard carries it too)
and `reruns`: per mutant the index, file, name, method, command, exit code, and
both passes (`pass`, `rerun`: outcome, seconds as the sum of the phases, the log's
path, the test timeout cargo-mutants set from its baseline, read from its
`debug.log`, and what the log names). `package` keeps `rerun/<n>/outcomes.json`
and `line.diff` and no mutant log (the second fold, below). The shard's limits
appear once in the lone command: `run` extends the stored command with them in
place, so `lone_command` drops them with the sharding and the output
(`LONE_DROPPED`) before `lone_reruns` appends them (the second fold).

Why `--in-diff` beside `--re`: cargo-mutants 27.1.0 lists every `StructField`
mutant of the selected files whatever `--re` and `--exclude-re` say (`cargo
mutants --list --file 'src/script/**/*.rs' -F zzzz_nomatch` lists
`arithmetic_room.rs:179:13: delete field message ...`; nine at `8264a95d`: one
each on the script, BEEF, Merkle and wire surfaces, five on the substrates'
`result_values/wire.rs`). The line's diff leaves them out; the name leaves out
the line's other mutants (`script.rs:708:13` carries `+= with -=` and `+= with
*=`, and the function's three at `702:5` span it): `-D` alone lists five there,
`-D` with `-F` the one. The judge still requires the one mutant alone. A tool
filing for the leak is the finder's to make (not made by this lane).

## The TMPDIR artefact, as read

cargo-mutants copies the source tree (reflinked where the filesystem allows) into
a scratch directory `$TMPDIR/cargo-mutants-<dir>-<random>.tmp`, builds and tests
every scenario there (the build products in the job's `CARGO_TARGET_DIR`), and
deletes the copy at the end unless `--leak-dirs`. Its `--output` holds what it
keeps: `mutants.out/outcomes.json` (each scenario's summary, phases and
durations, the log's path), `log/<scenario>.log` (the build and test output:
cargo's ``Running `<target>/debug/deps/<binary> ...` `` per test binary, and
libtest's `test <name> has been running for over 60 seconds` for each test past
a minute), `debug.log` (`Auto-set test timeout to <N>s`, the timeout it derived
from the baseline, and the scratch directory's path), `lock.json`, the
`caught.txt`/`missed.txt`/`timeout.txt`/`unviable.txt` lists, `mutants.json` and
`diff/`. Each lone re-run makes its own scratch copy, so it inherits nothing of
the pass's copy; it reads its own `outcomes.json`, its log and its `debug.log`'s
timeout. What the log names (the last test binary's file name, no host path, and
the tests named past a minute) is read into `run.json`'s `named` when the re-run
ends, not kept raw: no log is packaged. `lock.json`, `debug.log` and the logs
carry host paths and are not packaged.

## The judge

`collect`: a shard with the mark judges each pass timeout by its lone re-run
(`rerun_evidence`): the re-run finished under cargo-mutants 27.1.0, its baseline
the one green scenario, exactly one other scenario and that the mutant, its
outcome the one `run.json` records and not unviable, its exit code 0, 2 or 3.
Caught or missed replaces the timeout; a second timeout counts in the file's
`timeout` column and is listed in `timeouts` (the file, the mutant, the shard,
both passes' seconds and limits, the method, the last binary and the tests the
log names; since the second fold no log path, the log not being packaged). `viable = caught + missed`. A pass timeout with no re-run
fails closed (`timeout without its lone re-run`), as do a re-run of a mutant the
pass did not time out, two re-runs of one mutant, and shards under two rules. A
shard without the mark is judged as before (`viable = caught + missed +
timeout`); the result names the rule (`timeout_rule`). `judge`, which the
incremental night uses for a carried row, now reads the row's stored `viable`,
so a figure keeps the denominator it was measured with. `report` writes the
legend by the rule and the table `Timed out twice (#781), outside the
denominator`, one row per mutant.

A file whose every judged mutant timed out twice reads `UNJUDGED` (the fold on
the keeper's word of 2026-11-04 16:1xZ, refined):

> a timeout-only file (every viable mutant timed out twice) reads as its own
> status, UNJUDGED, never NO VIABLE MUTANTS, which stays the label for code the
> compiler refuses; UNJUDGED is non-failing when the file carries no floor, its
> mutants in the timeout table and the file listed by name in the record's
> census so nothing drops in silence; a floored file that is timeout-only FAILS
> with "floor has no measured file", since a floor is a claim and the oracle
> that cannot read it fails closed. Land it in #784 by a fold now, with a test
> pinning both cases (an unfloored timeout-only file UNJUDGED and green; a
> floored one FAIL), not as a row after: the judge is the thing being written.

error is `floor has no measured file: <file>`, the row's `below N% or no viable

## The record

`mutants_record.py`: `survivors` reads each shard's `run.json` and gives a
re-run mutant the re-run's outcome, with both passes' figures beside it; a
survivor is `missed` alone under the rule (`survived`, `survivor_count`). The
one-run record gains, under the rule only, `timeout_rule` and `timeouts` (the
twice-timed-out mutants, their own `.md` section, `## The timeout rows (#781)`)
and `totals.timeouts`; a survivor group carries no `timeout` count; the legend
says the rule. `shard_rows` counts a shard's outcomes after its re-runs and puts
every timed-out pass's minutes (the shard's and the re-run's) under `timed_out`
and the re-runs' baselines under `rerun_baseline`; `survivor_term` counts the
timed-out mutants and their minutes under their own heading
(`timed_out`, `minutes_per_timeout`, `rerun_minutes`), never in `survived`. The
two-run path follows the rule for its survivors. `floors` is unchanged: the
score rounded down, never lowered.
