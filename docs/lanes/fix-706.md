## How a row named a module before

`affected_tests.py`'s `Tree.uses` is a binary's source reading (`used_modules`) with
its row's reading (`row_modules`). On `ba0952c9` the row's reading was two patterns
anywhere in the row's line, `src/<m>/` and `` `<m>::` `` (with an optional
`crate::`, `bsv_rs::` or `bsv::`), and the source's reading took a crate-root
re-export as a whole word anywhere in the text once the text held any
`bsv_rs::{` or `bsv_rs::<Name>`. Both over-matched:

| Reading | What it took | Example |
| --- | --- | --- |
| the row's `src/<m>/` | a pointer to another file's witnesses | `auth_certificate_field_value_261` into `identity` (`src/identity/client_field_value_261_tests.rs`), `auth_key_strictness_sites_498` the same, `primitives_public_key_forms_498` into `wallet` (`src/wallet/substrates/result_values/...`): the "one wallet binary in its set by its row alone" of #703's docs fold |
| the source's re-export word | a word that is not an import | `WalletFaultFamily::Transport` as `auth` (`wallet_fault_439`, `wallet_fault_wire_439`), a comment's "Address" as `script` (`integration_tests`), overlay's `Protocol` as `wallet` (`overlay_admin_token_envelope_544`, `overlay_cross_sdk_tests`), a doc comment's "Certificate" as `auth` (`identity_lone_surrogate_566`); 16 binaries in all |

## The reading now

- **The row:** the table gains a Modules cell (the fourth). `row_modules` reads the
  cell's backticked names alone; the description names nothing. A row of four
  cells (the table before #706, read at an older commit or in a fixture of that
  shape, as #703's tests have) keeps the old patterns, so the night's comparison of
  a row's modules at two commits reads each commit as it was.
- **The source:** `used_modules` reads `bsv_rs::<m>` paths, a re-exported name
  through the crate (`bsv_rs::<Name>`, the leading name of each top-level item of a
  `bsv_rs::{...}` group, nested braces kept), an alias of the crate (`use bsv_rs as
  sdk;` reads `sdk::` the same: `kvstore_integration_tests`' support module names
  `sdk::transaction`), and, for a glob import of the root, every re-exported word.
  `error` and `util` are never named in a row (a change under `src/error*` reaches
  every target already; `util` is crate-private).
- **The guard** (`tests/arch_tests_claude_rows_name_modules_706.rs`) ports both
  readings to Rust without a regex crate (`module_sources`' `mod`/`#[path]` walk,
  the re-exports of `src/lib.rs`, the groups) and refuses a binary without a row
  and a row whose cell names fewer modules than the source. The refusal:
  `tests/<file>.rs: its row does not name <modules>; a row names, in its Modules
  cell, at least the modules its file's source names by a `bsv_rs::` path or a
  crate-root re-export (tests/CLAUDE.md, ## Files)`. Its fixtures and comments
  write the crate as `KRATE` and `<crate>`, so its own text names no module (the
  draft's fixtures had put the guard in the script, transaction and wallet sets).
- **The script** (`.github/scripts/rows_from_sources.py`) writes the cells from
  `Reading`'s sources (`affected_tests.Tree` underneath): the union of the row's files' modules, every
  module the cell already names, and the caller additions below; `--check` refuses
  as the guard does. Two readings, one in Python and one in Rust, because the
  guard must run in the Rust suite with no Python, and the plan and the night read
  the Python one. Where the Modules cell decides they agree: on `a5dd5459` with
  every cell set to `none`, both refuse the same 268 binaries with the same missing
  modules (review-fix-706). On `ba0952c9` they do not, by design: the Python
  `row_modules` reads a row of four cells by the old patterns, the guard reads it
  as naming none, so with the guard's file present the script refuses 273 and the
  guard 274 (`script_arithmetic_result_bound_374`, whose description names
  `src/script/`, the one more), and 20 of the refusals the two share name
  different missing modules. The script's
  tests are in `test_affected_tests.py` (`RowsFromSourcesTests`), which CI runs.
