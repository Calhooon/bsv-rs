# #752: the by-type questions send `certificateTypes` with `identityKey`

Base `56caa15d` (`origin/beta`'s tip at the lane's start, #750 landed:
`query`'s filters, whose question this lane corrects).

## The reference

The reference overlay's identity lookup service at `ts-stack@edf6e03`,
`packages/overlays/topics/src/identity/IdentityLookupService.ts`:

- `:74-82`: `requireLookupQuery(question, 'ls_identity', [...])` admits
  `attributes`, `certifiers`, `identityKey`, `certificateTypes`,
  `serialNumber`, `limit`, `offset`;
- `shared/queryValidation.ts:35-38`: any other own key refuses the whole
  question, `Invalid lookup query: unexpected field <key>`;
- `:97-100`: `certificateTypes` is a string array of at most 32 items, each
  base64 of 32 decoded bytes (trimmed; the alphabet, the padding and the length
  checked, the trailing bits not: `validationHelpers.ts:488-498`, so not a
  canonical check);
- `:136-143`: with `identityKey` and `certificateTypes` both present, the
  answer is `findByCertificateType` (`IdentityStorageManager.ts:315-339`:
  subject, type `$in`, the certifiers if any); the types alone are not read.

The reference wallet asks no by-type question: `Wallet.ts:1004`
(`discoverByIdentityKey`) sends `{ identityKey, certifiers }`; the SDK's
`IdentityClient.ts:736-740` sends `{ serialNumber }` for the revocation. The
overlay's allowlist and its `IdentityQuery` type (`types.ts:28-36`) are the
reference for the shape.

## The change

| Door | Before (`56caa15d`) | After |
|---|---|---|
| `discover_certificates_by_type(key, type)` | `{ identityKey, certificateType: type }` | `{ identityKey, certificateTypes: [type] }` |
| `query` with `certificate_type` | `certificateType: type` beside `identityKey`, `attributes`, `certifiers`, `limit`, `offset` | `certificateTypes: [type]` beside the same |
| `query` without a type | no type key | unchanged |

`IdentityQuery`'s own serde JSON (`certificateType` by its camelCase rename)
is untouched: the struct's serialization, not the lookup question.

## Finding, not changed

`discover_certificates` sends `{ identityKey, certificatesOnly: true }`;
`certificatesOnly` is not in the allowlist, so a reference host refuses that
door's question too. Outside the issue's two doors; a follow-up.

## The test

`tests/identity_question_752.rs`: a recording facilitator (its own, after
#744's `Answering`) behind `LookupResolver` with an `.invalid` host override
records each question's query and answers an empty output list. Three tests:
the by-type door's question, `query` with a type, limit and offset, and
`query` without a type. Each asserted question also passes the allowlist's
seven keys. 2 of 3 RED on `56caa15d` (scratch copy, its own target dir), the
no-type control green on both.

No fixture or vector carries the old question key: `grep -rn certificateType`
finds `IdentityQuery`'s serde test (`tests/identity_tests.rs:451`) and the
HTTP JSON substrate's #105 rename, neither a lookup question.
