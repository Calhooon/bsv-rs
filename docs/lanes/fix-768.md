# #768: the JSON lookup parse refuses what the reference's normalizer refuses

Base `81c312e2` (`origin/beta`'s tip at the lane's start, #762 landed).

## The reference

`ts-stack@edf6e03`, `packages/sdk/src/overlay-tools/LookupResolver.ts`:

- `:855-867`, the HTTPS facilitator: after `JSON.parse` it repairs each item's
  `beef` and `context` with `normalizeBRC100ByteFields` (`:858-863`; only when
  `type === 'output-list'` and `outputs` is an array), then
  `normalizeLookupAnswer(answer)`, and `throw new Error('Malformed lookup
  response')` on `undefined` (`:865-866`).
- `:305-307`, `dataRecord`: `null`, a non-object and an array are no record.
- `:389-406`, `normalizeOutputListAnswer`: `type` the string `output-list`,
  `outputs` an array of at most `MAX_LOOKUP_OUTPUTS`, every item admitted, one
  refused item refusing the answer.
- `:327-357`, `normalizeLookupOutput`: an object; `beef` `isByteArray`
  (`:288-303`: an array of integers 0 to 255), non-empty, at most
  `MAX_LOOKUP_BEEF_BYTES` (32 MiB, `:252-256`); `outputIndex`
  `Number.isInteger` from 0 to `0xffffffff`; `context` absent, or a byte
  array of at most 1 MiB; `txid` absent, or a string of 64 hex digits.
- `BRC100ByteEncoding.ts:126-146`, `normalizeBRC100ByteFields`: `{}` at a byte
  field is `[]`, the historical object form `{"0": b0, ..}` its bytes; a text
  is left as is (and then refused by `isByteArray`).
- `:2379-2406`, `completeTrackedLookup`: the thrown error a failure for the
  host.

`ts-sdk@9e3ede6` `src/overlay-tools/LookupResolver.ts`: the facilitator
returns `response.json()` as parsed (`:189`); `lookupHostWithTracking`
(`:518-528`) records `Invalid lookup response` for an answer without
`type: 'output-list'` and an array `outputs`. Both references record `{}` a
failure.

## The LOW host

`~/bsv/bsv-overlay-cloudflare` `crates/overlay-cloudflare/src/routes.rs:2395-2466`
(`lookup`): every JSON answer is `json_ok(&answer)` of this crate's
`LookupAnswer` (serde, `#[serde(tag = "type")]`, `outputs: Vec<OutputListItem>`
with `beef: Vec<u8>`), so it writes `type`, an `outputs` array and byte-array
`beef` always; an error is `json_error` with a non-2xx status, refused before
the parse. No site writes a shape the normalizer refuses; nothing kept lenient.

## The change

`src/overlay/facilitators.rs`, `parse_json_lookup_answer` and the new
`parse_lookup_output`, `lookup_byte_field`, `lookup_output_index`:

| Body | Before (`81c312e2`) | After |
|---|---|---|
| `{}` | `OutputList []`, success | `the answer has no string type member` |
| `[]`, `"x"`, `null`, `5` | `OutputList []`, success | `the answer is not a JSON object` |
| `{"type":5}` | `OutputList []`, success | `the answer has no string type member` |
| `{"type":"output-list"}` | `OutputList []`, success | `an output-list answer without an outputs array` |
| `{"type":"output-list","outputs":"x"}` | `OutputList []`, success | the same |
| `{"type":"output-list","outputs":[{"beef":[1]}]}` | `OutputList []`, success | `output 0 outputIndex is not an integer from 0 to 4294967295` |
| a good item beside one without `beef` | the good one, success | `output 1 beef is not an array of 1 to 33554432 bytes` |
| `"beef": "0102"` | `[1, 2]`, success | `output 0 beef ...` |
| `"beef": []` | `[]`, success | `output 0 beef ...` |
| `"context": null` | `None`, success | `output 0 context is not an array of at most 1048576 bytes` |
| `"txid": "ab"` | ignored, success | `output 0 txid is not 64 hex digits` |
| `"beef": {"0":7,"1":8}`, `"context": {}`, `"outputIndex": 1.0` | item dropped | read |
| `{"type":"output-list","outputs":[]}` | success | success |

Each error is `Malformed lookup response: <what>`, recorded by the resolver as
the host's failure. `byte_fields::byte_array` (the wallet substrates' reading
of `normalizeBRC100ByteArray`) is `pub(crate)` for the items.
