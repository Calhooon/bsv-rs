## The decision

One shape: the associated function the issue names, the wallet and the
originator leading the reference's seven parameters. A wallet-holding type
would be a second `PushDrop` constructor beside `PushDrop::new(key, fields)`,
whose struct holds a key and fields, not a wallet; nothing existing changes
signature. `wallet_key_lock` (the five sites, under `kvstore`, `identity` or
`registry`) is now `wallet_key_lock_at` at lock-before; the sibling takes the
position and stands under `wallet`, so a `wallet`-only build carries no dead
code.

Two residues, stated in the root `CLAUDE.md` row and the changelog: the key
text is read by `PublicKey::from_hex` (the reference pushes it unparsed), and
#545's odd-length opcode is inherited.

The witness file is gated on `wallet`, the door's own feature (the #545 file
it is modelled on is gated on its sites' features); it runs under
`--no-default-features --features wallet` too.

## The fold: the key text before the signature (the rule read, 2026-11-09)

The finding: the reference decodes the wallet's key text,
`toArray(publicKey, 'hex')` (`PushDrop.ts:166-172` at `ts-stack@edf6e03`;
`assertValidHex`, `primitives/hex.ts:6-17`, through `hexToUint8Array`,
`utils.ts:126-128`, throwing `Invalid hex string` for a text that is not hex),
