# Lane fix-854-shamir-interop: backup shares are BRC-140's; a named function recovers a backup an earlier release wrote (#854)

Base: `origin/beta` at `18ff3307`. Standard: BRC-140 (`key-derivation/0140.md`) at `bsv-blockchain/BRCs@f7f1520`. Reference: `ts-stack@edf6e03` (`packages/sdk/src/primitives/PrivateKey.ts`, `Polynomial.ts`), bundled with `bun build` and run under Node v22.18.0. Go: `go-sdk` at `2ca481c` and at master `0503af8` (`primitives/ec/shamir.go`, `primitives/keyshares/keyshares.go`), run on 2026-11-11 under go1.27.0 darwin/arm64 (lane go-run-854): at both shas go-sdk recovered 108 of 108 subsets of 54 share sets this crate wrote and refused the six 0.8.5 sets, and this crate recovered 102 of 102 subsets of 51 sets go-sdk wrote, the legacy reader refusing all 51. Decided by three design reads, 3 of 3: the reference's reader exactly at `from_backup_format` and `recover_private_key`, and a separate named function for the old form.

## The invariant

A backup share is BRC-140's text, `base58(x).base58(y).threshold.integrity`, and every share another SDK writes or reads is written and read here as the reference writes and reads it, verdict for verdict and in its words. A backup this crate wrote before the fix is read by one deliberate call that returns the key and never a `KeyShares`, so the old form cannot be written again.

## What changed

| Item | Before | After |
|---|---|---|
| The tag | `base58(sha256(key bytes))[..4]` (`GuMr` for the key 1) | `hex(HASH160(compressed public key))[0:8]` (`751e76e8`), `PrivateKey.ts:535` |
| The x coordinates | 1, 2, ..., n | BRC-140's MUST: `HMAC-SHA-512(seed, [i, attempt, r0..r31]) mod p`, a 64-byte seed per split, drawn again when 0 or used, the attempt after the fifth refused (`PrivateKey.ts:513-531`; BRC-140 "Share-coordinate generation") |
| The split's bounds | total unbounded; this crate's words | `2 <= threshold <= total <= 255`, the reference's words and order (`PrivateKey.ts:478-492`) |
| `from_backup_format` | four fields, base58 and a decimal threshold in any spelling, any tag | `fromBackupFormat` cell for cell (`PrivateKey.ts:55-102`): 1 to 255 shares, 256 UTF-16 units, the field grammars, the mismatches in order, the point through `from_string` |
| `PointInFiniteField::from_string` | two fields, any base58, reduced mod p | `Polynomial.ts:32-49`: 129 units, 1 to 64 base58 characters a field, its own text again |
| `recover_private_key` | this crate's words; a duplicate reached a zero inverse | `fromKeyShares` (`PrivateKey.ts:575-623`): the collection, too few, canonical coordinates, duplicates among the leading T, `f(0) mod n`, `Integrity hash mismatch` |
| `to_backup_format` | `Vec<String>`, no check | `Result<Vec<String>>`, `toBackupFormat`'s checks (`PrivateKey.ts:104-118`) |
| `split_private_key_with` | `(key, t, n, coefficients)` | `(key, t, n, coefficients, seed: &[u8; 64], draws: &[[u8; 32]])`, one draw per attempt |
| new | | `shamir::recover_private_key_from_legacy_backup(shares: &[String]) -> Result<PrivateKey>` (`src/primitives/bsv/shamir_legacy.rs`) |

BRC-140 and the reference agree on the coordinate procedure (one byte each for `i` and the attempt, 32 fresh bytes, at most 5 attempts), so nothing stopped for the upstreams. Go draws with `i` and the attempt as 4 big-endian bytes each (`shamir.go:71-80`, read, not run), a counter no reader sees.
