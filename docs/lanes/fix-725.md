Base `c719c639` (`origin/beta`'s tip at the lane's start, #721 landed); the
pre-#721 base for the RED runs is `0d8546c0`. From #724's strength read: three

## The witness

`tests/support/identity_beef_subject_725.mjs` uses #721's bundle recipe
(`git archive edf6e03 packages/sdk packages/wallet/wallet-toolbox/src`, #553's
tsconfig, `parseEvidence` exported, `bun build` 1.3.11) and runs under
`~/.nvm/versions/node/v22.18.0/bin/node`. The transactions are #721's, plus a
middle and a tip for the chain: the chain's grandparent is #721's parent. The
shapes are written by the reference's own writers: `Beef.toBinary` and
`toBinaryAtomic` sort the entries, and `toWriter` writes them in the order held
for the absent subject, because `toBinaryAtomic` throws for a subject it does
not hold. For each shape the recorder writes the bytes, the wire order,
`parseEvidence`'s pick or refusal and the check that refused, replayed through
`Beef`'s public methods because `parseEvidence`'s error carries only
`invalid-evidence`. It also writes `parseResults`' outcome under the toolbox
wallet's verifier. Two runs are byte-identical.

This crate's writer (`to_writer`, `to_binary`, `to_binary_atomic`) builds every
recorded BEEF byte for byte. On these shapes the two sorts agree: the txid-only
entry comes before the raw one, and the chain is written grandparent, parent,
subject. The two shapes are merged newest first, so the sort decides the order.
