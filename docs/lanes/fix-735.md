## The field

`OutputListItem::txid: Option<String>`, serde name `txid`, `default` and
`skip_serializing_if = "Option::is_none"`: a body without it reads as before
and writes as before. The JSON reader (`parse_lookup_output`,
`src/overlay/facilitators.rs`) already refused a `txid` that is no string of
64 hex digits with the whole answer (#768, `normalizeLookupOutput`'s
`:347-350`); it now keeps the text as given (`:356`, the case kept: the
reference lower-cases only at the comparison). The binary reader sets each
output's `txid` to its outpoint's hex, `to_hex` of the 32 bytes as read, the
reference's `toHex(r.read(32))` (`:886`), no reversal on either side.

## The check

`admit` (`src/identity/evidence.rs`) runs `parse_evidence` unchanged, then,
on an admitted subject, `hint_disagrees`: a hint present whose
`to_ascii_lowercase()` is not `subject.id()`. The reference's `toLowerCase`
and Rust's ASCII lowering differ only outside ASCII, where no text can equal
a lowercase hex txid on either side. A disagreement increments the client's
`HintContradictions` (an `AtomicU64`, a private field of `IdentityClient`),
read by `IdentityClient::txid_hint_contradictions()`. Counting only admitted
outputs: the reference throws at the hint before the output-index check and
the graph walk, but every one of those throws is the same skip, so the
verdict for a refused output does not depend on which check fired; the count
is defined over outputs this crate reads.

`src/identity/client.rs` is over the ratchet's 800 lines, so it could not
grow: the field and its initializer are two lines, `new` now delegates to
`with_resolver` (eleven lines fewer, the same body), and the accessor lives
in `evidence.rs` beside the type (the field `pub(super)`).
