## The finding (issue #110 and its comment, from the oracle-fuzz lane, #82)

`SocketIoPacket::decode` (`src/auth/transports/socketio/codec.rs:280-345`) accepts frames whose encoding decodes to a different packet. Two things in the decoder: the digit run after the namespace is read as an ack id for every type, and `Connect`, `Disconnect` and `ConnectError` have no field to carry it, so `decode("00")` drops the `0` and the packet encodes as `"0"`; a CONNECT payload is taken whatever its JSON type, so `"0\n0\n"` decodes to a CONNECT with `data: Some(0)`, which encodes as `"00"`. The comment's second input (`0000000   8147…`, base64 in the issue) reads a digit run as an id and a number past `u64` as a float, encodes as `08.147…e36`, which does not decode. A third thing to read on the way: an id past `u64` is consumed and dropped (`parse().ok()`, `:300-306`).

## The reference

socket.io-parser 4.2.7, the parser `socket.io` ^4.8.3 ships; `@bsv/authsocket` depends on it (`ts-stack@edf6e03` `packages/messaging/authsocket/package.json`). A copy is on this host: `~/bsv/bsv-stack-lean/tools/n1-paid-send/node_modules/socket.io-parser/build/cjs/index.js` (cite its version from the `package.json` beside it). `decodeString` (`:178-247`) reads the digit run as the id for every type, CONNECT included, and keeps it on the packet; `encodeAsString` (`:77-100`) writes the id of every packet that has one, so `"00"` round-trips there; `isPayloadValid` (`:256-275`): CONNECT needs an object (`isObject`, `:340-342`, `[object Object]`, so an array is not one), DISCONNECT no payload, CONNECT_ERROR a string or an object, EVENT and BINARY_EVENT an array whose head is a number or a string outside `RESERVED_EVENTS` (`:16-23`), ACK and BINARY_ACK an array; anything else, and a payload that is not JSON (`tryParse` gives `false`), is `"invalid payload"`. Read `decodeString` and `encodeAsString` whole and tabulate every point where this codec reads or writes differently (the three above and any other: the namespace without a comma, an empty digit run, a binary type `5`/`6`), in the REPORT.
